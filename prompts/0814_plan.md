# 8. Definition-completeness requirement

The goal is **definition-complete foundation, lemma-nearly-complete foundation**.

For each concept, explicitly classify planned declarations as:

* **MUST DEFINE NOW** — the mathematical object/operation is part of the foundation and later clients should not need to invent it;
* **SHOULD PROVE NOW** — routine API lemmas needed for ergonomic use and rewriting;
* **MAY DEFER** — genuinely nontrivial mathematical results that are not needed to make the API coherent;
* **OUT OF SCOPE** — intentionally excluded from this construction round.

This classification is important.

A plan is not complete if, for example, it says “support general graph walks” without listing the raw walk/trail/path/circuit/cycle objects and their realization predicates.

Conversely, do not bloat the foundation plan by insisting on every sophisticated connectivity/tree theorem before the definitions can be used.

# 10. Important fixed design constraints

The final plan must preserve all of the following.

## General edges

```text
Edge α β
Arc α β
```

remain bundled.

For general graphs:

```text
E(G) : Set (Edge α β)
E(G) : Set (Arc α β)
```

respectively.

The tag is `tag`, not `endpointsLabel`, and is not assumed globally unique.

Endpoint images are explicitly lossy:

```text
edgeEndpointPairSet
arcEndpointPairSet
```

Do not let endpoint-pair images masquerade as actual edge sets.

## Walk architecture

Preserve the graph-independent validated chain:

```text
VertexSeq
→ SimpleWalk
→ SimplePath
→ SimpleCycle
→ G.Is...In
```

Do not convert it into Mathlib-style graph-indexed dependent walk carriers.

General raw walks remain graph-independent as well; identity-sensitive graph statements are expressed by realization predicates.

## Subgraphs and transformations

Induce/delete/restrict stay in the same ambient vertex/edge types.

Use:

```text
H ≤ G
H ≤s G
H ≤i G

induce
restrictEdges
deleteEdges
deleteEdge
deleteVerts
deleteVert
deleteEdgesBetween
deleteArcsFromTo
reverse
mapVertices
relabelVertices
relabelTags
```

with meanings fixed by `NAMING.md`.

No lossy implicit coercions.

## Finite API

Only mathematical Set/Finset APIs belong in this foundation round unless a real existing algorithm client forces otherwise.

Do not create a speculative executable graph representation.

## Attached edge data

Weights, costs, and capacities are data on actual edges/arcs, not new graph types and not unrestricted functions on general-edge tags.

## Contraction

No contraction Lean API in this plan.
